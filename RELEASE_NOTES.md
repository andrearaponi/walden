## Walden v0.2.0

This release broadens Walden's agent support, makes the CLI self-documenting, and clears out a set of inconsistencies that hurt the first-run experience.

### Highlights

**Now runs across four agents.** The Walden skill installs for Claude Code, Codex, GitHub Copilot, and OpenCode. The same `SKILL.md` is portable; `setup.sh` places it where each agent expects it.

**Claude Code uses a real Agent Skill.** Walden now installs as a model-invoked skill (`~/.claude/skills/walden/SKILL.md`) that Claude activates by intent — no more typing `/walden`. See *Breaking changes* below.

**A real `--help`.** `walden --help`/`-h` (and bare `walden`) print an honest `Usage:` block — every command with a description and the key flags — instead of the old, misleading `Planned commands:` header.

**Decision Checkpoint Protocol.** During drafting the skill stops at genuine forks with a `[decision: ...]` marker and records autonomous choices inline, so specs don't silently bake in unreviewed assumptions.

### Breaking changes

- The `/walden` slash command for Claude Code is **removed**. Walden is now a model-invoked skill. `setup.sh` migrates you automatically — on install and uninstall it deletes the legacy `~/.claude/commands/walden.md`. After upgrading, invoke Walden by describing the spec work (e.g. "let's write the requirements for X with Walden") instead of typing `/walden`.

### Fixed

- The CI workflow generated by `walden repo init` referenced a non-existent Python script and broke every PR touching `.walden/**`; it now installs and runs the `walden` CLI.
- The bundled `todo-app-demo` used an undocumented proof keyword (`argv:`); aligned to the canonical `command:`.
- Removed the last stray Python reference from the generated `lessons.md` header.

### Install

```bash
go install github.com/andrearaponi/walden/cmd/walden@v0.2.0

# or: build the binary and optionally install the AI skill
git clone https://github.com/andrearaponi/walden.git
cd walden && ./setup.sh
```

Pre-built binaries for linux/darwin × amd64/arm64 are attached to this release.

Still zero external dependencies. The JSON contract remains `schema_version: v0alpha1` and will stabilize to `v1` at v1.0.0.
